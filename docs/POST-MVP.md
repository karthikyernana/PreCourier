# Post-MVP Scope

This is the durable queue for the remaining product. A future AI agent should select one phase, read its PRD references, inspect current source, implement the smallest complete lifecycle, add tests, and update this file with evidence.

## Ordered phases

1. LLM address extraction and message composition behind deterministic verification.
2. One approved production messaging channel, selected with the first design partner: WhatsApp provider or DLT-capable SMS.
3. One live carrier/shipping-aggregator adapter with serviceability, address validation, pre-label hold, cancellation, and outcome reconciliation.
4. Custom REST store adapter, then WooCommerce integration, then Shopify GraphQL-first integration.
5. Signed inbound and outbound webhooks, provider event IDs, replay protection, delivery log, retry worker, and reconciliation.
6. Razorpay merchant-owned Payment Links, verified webhooks, prepaid conversion, partial payment, expiry, refund, and ledger reconciliation.
7. Beta-Bernoulli action/cause effectiveness updates from eligible outcomes.
8. Merchant-specific training, calibration, model registry, fallback, drift, and shadow promotion.
9. Merchant console: onboarding, queue, order detail, conversation, policy, money, audit, model health, and costliest-mistake reports.
10. CSV import, historical replay, onboarding backtest, and report exports.
11. Team roles, API-key scopes, test/live environments, approval workflows, and administrative audit.
12. Hindi and selected regional-language templates, transliteration, language preference, and extraction support.
13. Shopify public-app privacy webhooks, OAuth, protected-customer-data review, rate-limit handling, and uninstall lifecycle.
14. Production security: PostgreSQL, migrations, encryption, KMS secrets, RBAC, SSO/OIDC, MFA, retention, deletion/anonymisation, backups, restore tests, incident response, and enterprise evidence.
15. Multi-store, multi-warehouse, multi-carrier, consolidated global-vendor India operations, and currency/reporting boundaries.
16. SLOs, queue/provider metrics, circuit breakers, dead-letter handling, watchdogs, reconciliation jobs, status reporting, and runbooks.
17. Uplift or treatment-effect models after sufficient merchant outcomes.
18. Chaos-mode demonstrations and provider-failure drills.

## Phase rule

No phase is considered complete because an enum, schema table, interface, demo card, or documentation section exists. Completion requires source, tests, operational behavior, and a documented India/security/compliance impact.

## Commercial sequence

- Start with managed Indian advisory pilots.
- Prove incremental recovery against merchant history.
- Add one real pre-label carrier path.
- Add production messaging and payment only with provider evidence.
- Expand to platform and enterprise integrations after the first path is reliable.
